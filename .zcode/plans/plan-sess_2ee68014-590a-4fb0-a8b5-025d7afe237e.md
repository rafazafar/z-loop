# Implementation Plan: GitHub Issue Blocker Filter Toggle

## Summary
Add an "Only unblocked issues" toggle to GitHub automations (defaulting to `true`). When enabled, the GitHub issue scheduler inspects issue dependencies (both native GitHub `blockedBy` relationships and inline `## Blocked by` markdown sections) and enqueues only issues whose blocking issues are closed.

---

## 1. Data Model & Schema (`src/automations.ts`)
- Update `AutomationInput` interface:
  ```ts
  export interface AutomationInput {
    id?: string;
    name: string;
    enabled: boolean;
    trigger: 'interval' | 'files' | 'github';
    intervalMs: number;
    watchHead?: boolean;
    filterBlocked?: boolean; // New field, defaults to true for github triggers
    path?: string;
    label?: string;
    work: WorkInput;
  }
  ```
- In `defineAutomation`:
  - Validate `input.filterBlocked !== undefined ? typeof input.filterBlocked === 'boolean' : true`.
  - Persist `filterBlocked` in `definition_json`.

---

## 2. Blocker Evaluation in GitHub Scheduler (`src/automations.ts`)
- In `Scheduler.tick`:
  - Update `gh issue list` fields to include `blockedBy`:
    ```ts
    ['gh', 'issue', 'list', '-R', repo, '--state', 'open', '--label', label, '--limit', '100', '--json', 'number,title,body,url,blockedBy']
    ```
  - Also fetch list of all open issue numbers in the repository (`openSet: Set<number>`) or map from the issue scan to evaluate blockers:
    - **Native GitHub blockers**: Inspect `issue.blockedBy?.nodes`. If any node has `state !== 'CLOSED' && state !== 'MERGED'`, consider it open and blocking.
    - **Inline markdown blockers**: Parse `issue.body` for `## Blocked by` / `[Bb]locked by` sections followed by `#(\d+)`. If any referenced issue number is in `openSet`, consider it blocking.
  - If `definition.filterBlocked !== false` (defaulting to true) and the issue has any open blocker:
    - Skip enqueueing this issue on this scan.
    - As soon as the blocker issues are closed and merged, subsequent scans will detect the issue is now unblocked and enqueue it.

---

## 3. Web Dashboard UI (`web/forms.js` & `web/app.js`)
- In `web/forms.js`:
  - In `openAutomation(row)`:
    - Add a `filterBlocked` select/checkbox field:
      - Label: `Blocker check`
      - Options: `[['true', 'Only unblocked issues (Recommended)'], ['false', 'All issues (ignore blockers)']]`
      - Value: `String(value.filterBlocked !== false)` (defaults to `'true'`)
      - Visibility: Visible only when `Source` is set to `GitHub issues`.
  - On submit, serialize `filterBlocked: filterBlocked.value === 'true'`.
- In `web/app.js`:
  - In the automation list card, display `· unblocked only` in `card-meta` when `filterBlocked !== false` on a GitHub trigger.

---

## 4. Automated Tests (`test/automation.test.ts`)
- Add unit tests:
  - Verify `defineAutomation` accepts `filterBlocked: true|false`.
  - Verify GitHub issue trigger filters out issues with open native `blockedBy` nodes when `filterBlocked: true`.
  - Verify GitHub issue trigger filters out issues with open inline `#123` references when `filterBlocked: true`.
  - Verify GitHub issue trigger enqueues all issues when `filterBlocked: false`.
  - Verify that when the blocker issue closes, the previously blocked issue is enqueued.
